## 官方签名组件自动更新验收

对应 `CHANGELOG.md` 的 1.1.18 修订。迁移前需要一次明确授权；迁移后由独立、稳定的受保护更新任务验证官方签名，普通应用只投递请求。

- 全仓 667 项测试，665 项通过，2 项因本机符号链接权限跳过。真实 Windows CNG RSA3072/PSS、DPAPI、错误密钥、重复 JSON、版本回放和构建签名门禁通过。更新事务及原生 Job Object 测试覆盖中断恢复、超时子进程回收和回滚。
- 同一隔离实例真实安装已发布旧后台，再安装本次正式候选组件；非空旧 ledger、旧独立备份包及任务配置的 SHA-256 保持一致。没有运行或改写正式任务和正式安装。
- 高权通道实际拒绝坏签名；合法签名的失败安装器退出后，原 current 记录和任务 XML 恢复，旧任务随后仍实际完成了一次备份。
- 普通用户进程从私有新版应用副本默认发现签名包，投递后实际更换了源文件、构建指纹和安装代；没有调用迁移安装入口或 UAC。更新通道始终保留在初始受保护安装代，失败版本不会切断修复通道。
- 私有升级 revision 仅用于证明真实组件替换，不能进入正式发布；构建门禁同时比较唯一应用版本、派生组件基础版本、源码、安装器及签名清单。
- 升级后由 Windows 在 18:24 自动触发 Zotero 夹具备份，18:25、18:26 两个后续检查周期没有重复版本；新版本的数据库及归档独立校验通过。旧签名包回放被高权端拒绝，可用新后台保持不变。
- 真实旧安装标记在自动升级后可复现过期“重新授权”提示。普通 API 的只读状态归一化已实测清除该误报，同时保留真正的自动更新失败原因，原标记文件没有改写或删除。
