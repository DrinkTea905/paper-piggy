# 后台组件自动更新方案

状态：2026-10-30 已实施并完成隔离环境的原生迁移、签名升级、失败回滚及升级后定时备份验收。正式安装保持只读；范围与限制见[备份恢复验收记录](../开发/备份恢复验收记录.md)。

## 目标与现状

用户要求后续更新小猪时，无需再单独点击管理员确认；保留当前自动备份、登录补跑及正式目录只读边界。

现有后台只从受保护目录加载固定清单中的代码，普通应用没有改写这些文件或修改任务 action 的权限，也没有已部署的签名更新入口。因此从现有版本迁移到免重复授权更新能力，仍需一次明确的管理员授权。不能通过放宽任务权限、加载可写应用代码或复用恢复入口替代迁移。

## 推荐方案

- 保留已验证的备份及恢复业务链路，新增受保护的官方组件更新入口；普通应用只负责下载和投递更新请求。
- 一次迁移将固定验证公钥和更新入口写入保护目录。发布私钥只保存在发布环境，不进入源码仓库、应用或用户备份。
- 后台只接受签名覆盖产品标识、组件版本、文件清单、大小和 SHA-256 的官方更新；拒绝未知密钥、篡改、旧版重放、路径越界和任意命令。
- 备份空闲时完成受保护暂存、完整校验、预检、切代和失败回滚；正在运行的备份不被强行结束。更新入口保持可用，更新失败时保留可用旧组件。
- 主程序升级时自动衔接后台升级及状态反馈，不再要求用户单独点击后台更新。正常官方更新无重复 UAC；不调整 Windows 的 UAC 策略。
- 原任务、周期、位置、保留数量、历史备份、浏览器关联及登录资料保持原位。首次配置其他电脑仍需建立该电脑的授权关联。

## 验收范围

在隔离实例中验证：迁移完成后的普通权限应用更新不调用 runas；官方签名组件能自动升级；升级后小猪关闭时系统仍可定时备份和补跑；篡改、错误签名、旧版重放、路径攻击和切代中断均保留旧组件；忙碌时等待，失败持久记录；不触碰正式安装或真实来源，不绕过 Windows 权限。

实施时同步产品内新手指引、Agent 指引、主 README、独立教程及发布说明。现有版本已开启的登录补跑不依赖本改造，继续照常工作。
