## 为什么有这一轮

v3（重规则）与 v4（轻规则）连续失败。v4 的复盘见 [`v4失败复盘.md`](v4失败复盘.md)，三条根因：
① 诊断出"句子层没有素材"却一句真刊原文都没给；② 零前向验证就交付；③ 一次成型，无迭代。

用户 2026-08-14 定的三条硬约束（本轮一条不减）：

1. **必须给句子**——训练产物里必须有成段真刊原文作为阅读对象，不是 25 字碎片，也不是填空模板。
2. **前向验证是唯一验收**——跑完真写的稿子并通过盲读之前，不许交付、不许宣布完成。指标只是体检。
3. **必须迭代**——至少两轮"试跑 → 看成品 → 改规则 → 再试跑"，每轮留成品与判定记录。

### ★ 铁律：本目录只进本地 git，永不 push（用户 2026-08-14 拍板）

台账里必然嵌着**用户四份未发表论文的原句**（病症清单里已有几十条）与真刊对照片段。
`.gitignore` 挡住的是语料、范例库、试写稿三类，**挡不住台账本身**——而台账不含句子就退回
v3「只给定位不给句子」的老路，等于自废本轮的核心改动。

因此本目录（`docs/设计/少年司法初稿v5/`）的处理规则是：

- **照常 `git add` / `git commit`** —— 版本历史是防丢失与可回源的手段（v3 全部实测台账丢失、阈值今天无法回源核验，就是没有这一层的代价），且随 OneDrive 跨机同步。
- **永不 `git push`** —— 发版时只推送与代码相关的 commit。推之前先跑：

```bash
git log origin/main..HEAD --name-only | grep "少年司法初稿v5" && echo "⛔ 含 v5 台账，不要推"
```

- 若将来确实要公开某部分成果，**另写一份不含未发表原句的公开版**，不要直接推台账。
