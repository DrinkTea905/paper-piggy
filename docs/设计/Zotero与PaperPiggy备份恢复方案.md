# Zotero 与 PaperPiggy 备份恢复方案

状态：2026-10-30 已按用户确认方案实施，并完成隔离环境的真实多卷 VSS 备份和恢复验收。验收范围、证据与限制见[备份恢复验收记录](../开发/备份恢复验收记录.md)；版本及发布变更以 `config.APP_VERSION` 和 `CHANGELOG.md` 为准。

## 1. 两类独立任务，同页管理

- 在现有“备份与恢复”页面管理 PaperPiggy 备份和 Zotero 完整备份，各自产生可独立恢复的完整版本，不依赖增量链，也不互相依赖。
- Zotero 备份包含用户选定的实际数据目录，以及对应的整个用户配置目录：题录、附件、笔记、批注、分类、标签、样式、转换器、插件、prefs.js 和其他插件配置均在范围内。
- 数据与 profile 中的嵌套 SQLite 数据库及其关联文件也须覆盖，不能只处理根目录的 zotero.sqlite。源目录内现存的历史文件不因扩展名或目录名称被擅自清理。
- PaperPiggy 保留现有知识库资产范围及“包含索引”“包含 API 密钥”等选择，增加已关联专用浏览器资料。浏览器来源以现有浏览器关联为唯一依据，不扫描或纳入其他日常浏览器。
- 浏览器备份覆盖整个关联资料目录中的必要内容，包括根层 Local State、各 profile 的登录记录、标签、插件、站点数据及配置；只排除有明确清单的可再生缓存。不能把 Local Storage、IndexedDB、Service Worker 等站点持久数据仅凭名称当作缓存排除。
- 不加密，完整保留所选配置；保留浏览器原有加密文件，不解密导出密码，也不提取系统级凭据。备份文件须由用户保护。
- 源目录及目的地通过应用配置和界面发现、核对，不把本机私有绝对路径写入出厂源码或公共示例。

## 2. 运行中备份与一致性

- Zotero 和浏览器保持运行时可以备份，不强制关闭或暂停用户程序。
- 使用 VSS 将同一次任务涉及的来源卷加入同一个 snapshot set。跨卷来源不能分别创建两个快照后冒充同一时点。
- 用户接受一次管理员授权，以配置受保护的后台备份能力；PaperPiggy 的普通界面不因此整体提升权限。高权限组件不能直接执行可由普通用户任意改写的代码或任意命令。
- 当前机器没有 diskshadow.exe，不能把它当作现成运行依赖；实现须使用真正支持同批多卷快照的路径，并完成实机验收。
- VSS 不等于 Zotero 或浏览器原生事务协调。备份只承诺快照时已经落盘的内容；不承诺取得尚在内存、尚未保存的修改。
- 从静态快照读取来源，在副本中处理 SQLite 恢复及完整性检查，不在活动源库上执行修复、checkpoint 或写操作。
- 同时校验文件清单、内容哈希、归档可读性、数据库及所声明的附件覆盖情况，不能仅凭复制进程退出码或 ZIP CRC 宣称可恢复。
- 快照或校验失败就记录失败，不降级为直接复制正在变化的数据库，不生成成功恢复点，不删除既有成功版本。
- 结束时只释放本次任务创建的快照，不清理既有系统还原点或其他备份软件的快照。
- 运行中备份的正式验收必须包含持续写入、WAL 活跃、嵌套插件数据库及跨卷来源场景；当前只读调查不算热备份验收。

## 3. 调度与保留

- 两类任务均允许用户在小猪界面选择备份位置、周期和执行时间。目的地由用户自行选择；未选目的地、未完成组件配置时不能开启计划。开发验证使用隔离的来源与目的地，不代替用户建立真实数据备份计划。
- 不依赖 PaperPiggy 界面已打开；默认登录 Windows 后检查并补跑错过的计划。补的是当前状态，不试图制造已经错过的历史时刻版本。
- 各任务独立防重入；计划触发、登录补跑与手动点击不能并发备份同一任务。
- Zotero 常规成功版本保留目标为 2 份。PaperPiggy 保留份数沿用其已有设置并可单独调整，不把 Zotero 的选择静默覆盖到已有任务。
- 先完成新包，校验并登记成功，再清理超出保留数量的本任务最旧成功版本。创建新版本所需空间不足时失败，不先删旧包腾空间。
- 清理资格依据任务归属、来源及成功登记确定，不能只根据文件名前缀、目录位置或修改时间推断。
- 不删除现有“过时备份”目录及其内容，不接管其他任务、其他电脑或用户手工放入的旧备份。
- 新备份失败时保留已有成功版本并持久记录原因。清理旧版失败时保留新成功版本及尚未清理的旧版，明确显示“备份成功，清理失败”，不静默忽略。
- 失败、取消、空间不足、路径不可用及未完成任务的状态应在重启后仍可查；不能用上次尝试时间冒充上次成功时间。

## 4. 恢复

- 提供恢复到新目录供验证，以及用户明确确认后的原位恢复。
- 新目录恢复不覆盖当前正在使用的来源。原位替换 Zotero 或浏览器资料前，要求用户退出对应程序；不强制结束进程，也不关闭其他日常浏览器。
- PaperPiggy 自身原位恢复须停止进行中的写入，先断开 MCP，再退出小猪。请求经校验后排入后台，等待应用退出后替换当前数据家；恢复期间不得重新打开小猪。无原生关闭桥时提示用户手动退出，不把关闭网页标签视为后台已退出。
- 原位恢复前单独保留当前目录作为恢复回退件；不计入常规保留份数，也不自动删除，由用户手动清理。
- 跨卷恢复须有可恢复的操作记录；中途失败应回滚或明确保留可接续状态，不能留下数据目录与配置目录分别属于不同版本而仍提示成功。
- Zotero 恢复后保持备份中的原自动同步设置，不自动禁用同步，也不自动替换云端库。恢复确认页说明：后续同步可能重新应用云端较新的修改或删除。
- 兼顾本机、重装系统及换机：备份所选 profile 的注册关联元数据与 Zotero 版本；恢复时核对目标路径、兼容版本及 profile 关联，保留其他 profile 的注册信息。
- 浏览器同样支持同机回退及重装、换机时的资料迁移；Windows、浏览器加密绑定及网站规则可能使登录失效，异机不承诺免登录，必要时由用户重新登录。
- 不恢复或修改系统级加密环境来绕过浏览器保护，不自动登录或主动开启云同步，不自动下载或安装 Zotero、浏览器、插件及其他外部工具。还原备份中已有的插件文件属于配置恢复。

## 5. 实施与验收边界

- 实施限定开发仓库；正式安装目录只读，用户现有 Zotero、浏览器及历史备份不得用于破坏性恢复测试。
- 在临时数据、临时 profile、独立浏览器资料及独立端口上验证，不能借用正式浏览器调试端口。
- 验证同批多卷快照、活动数据库写入、附件与插件覆盖、哈希及数据库校验失败、进程中断、登录补跑、并发触发、空间不足、任务间互不清理和历史备份保护。
- 恢复测试包含新目录、同机原位回退、跨卷中断回滚、换路径/profile 注册、原自动同步设置保留及运行中拒绝覆盖。
- 浏览器测试使用独立测试站点和测试资料，核对配置、站点数据及同机登录记录恢复；不以真实用户 Cookie 或密码的提取作为验收手段。
- 升级须兼容现有 PaperPiggy 备份的列出、校验与恢复；旧包没有浏览器资料时明确显示其覆盖范围，不假称已包含。
- 任务配置、归属登记、成功记录和受保护组件的兼容性须在应用升级及恢复默认设置时明确保留，不能产生重复计划或悄悄重置目的地、来源和保留策略。
- 产品内新手指引、Agent 指引、主仓库 README、独立教程及发布说明随最终实现同步。
