# 专题工作流训练方法

> 状态：今后开发或重训任何专题工作流前必须先读。  
> 本文规定的是“从素材中提炼工作流规则”的方法，不是模型训练、微调或知识库维护流程。

## 1. 适用情形

用户提出下列需求时，先读取本文，再制定专题方案：

- 新建某一学科、主题或文体的专门工作流；
- 用一批范文改进既有工作流；
- 要求子代理批量读取、对抗、总结素材；
- 把一个已经训练过的专题工作流抽象成暂用通用版；
- 判断现有素材是否足以支持工作流开发。

## 2. 边界

1. “训练”是提炼可迁移的研究与写作步骤，不训练基础模型，也不模仿特定作者文风。
2. 训练素材以用户合法取得的完整原文为准。PaperPiggy 可以作为只读的原文访问入口，但训练产物不依赖其索引、摘要、Wiki 或项目记忆，也不写回这些位置。
3. 默认不调用 SiliconFlow 或其他付费模型，因此不计算 API 预算。只有用户明确要求实际调用外部付费服务时，才另行估算并确认。
4. 默认不做匿名 A/B 测试。匿名 A/B 仅在用户明确要求时采用；常规验证使用真实任务、结构化质检和失败案例复盘。
5. 不修改原始论文、Zotero 或用户正式安装目录。

## 3. 先分清“领域”与“任务类型”

专题工作流至少由两轴决定：

| 轴 | 例子 |
|---|---|
| 领域 | 少年司法、刑法、民法、数字司法 |
| 任务类型 | 论文初稿、综述、案例研究、实证报告 |

同一领域的不同任务类型必须分别训练。论文初稿与综述可以共享素材，但不能共用一套文章卡、规则卡或完成标准。

专题论文初稿的训练还必须分成两个互不替代的层次：

1. **研究可靠性层**：问题、法源、概念、规范链、理论前提、证据能力、竞争观点、领域边界和防错；
2. **成文技艺层**：问题怎样进入、创新怎样成立、理论怎样操作化、章节怎样依赖、段落怎样推进、首尾怎样兑现、
   法学表达怎样控制强度、来源与作者框架怎样保持归属。

“研究可靠”不能补偿结构和论证失败，“文字成熟”也不能补偿虚构来源、证据越级或领域规则缺失。训练、验证和评分均须分开记录。

同一任务类型内部若只是论证路径不同，而触发条件、必要输入、交付形态和完成标准大体相同，优先设计成
**一个工作流内的少量路线**，不要为每种写法都新建顶层工作流。只有上述要素发生实质变化时才拆分工作流。
路线通常控制在两条；确有必要时最多三条。实证、比较法、制度史等通常作为可叠加模块，不自动升级为新路线。

## 4. 素材选择

### 4.1 先按方法作业选文

期刊层级只用于建立候选池。是否进入训练集，取决于文章是否实际完成了目标工作流需要的方法作业。

- 法教义学素材重点看：规范识别、概念界定、解释、体系化、要件与法律效果、反例、救济、解释论与立法论边界。
- 理论—制度建构素材重点看：概念层级、理论前提、竞争模式、正当性、中层命题、立法批判、制度落点与实施边界。
- 综述素材重点看：范围界定、检索边界、分类轴、学说谱系、争点整理、证据评价、研究空白的限定表达。
- 纯政策评论、材料介绍或仅有价值宣示的文章，可以作为反例或边界样本，不能自动成为正面范本。

### 4.1a 先冻结素材准入规则

每个专题训练方案必须在选文前明确并记录：

- 允许的语言；
- 允许的发表地区或法域；
- 允许的文献类型；
- 期刊等级下限或白名单；
- 是否必须有完整全文；
- 明确排除的来源及理由。

先按这些客观条件机械过滤，再按方法作业人工筛选。后续发现材料不足时，不得静默放宽标准；
应报告缺口，由用户决定补材料还是调整准入范围。

### 4.2 建立四层素材池

1. **领域核心**：直接处理目标领域的代表性文章。
2. **方法补强**：相邻部门法中方法动作清楚的文章。
3. **对抗样本**：同题不同立场、不同方法或结论相反的文章。
4. **文体样本**：与目标交付形态一致的高质量成品，例如综述、学术史、论文初稿及其修改材料。

### 4.3 重要作者纵向组

若某位作者在目标领域或相邻方法领域形成了持续、多篇且相互修正的研究序列，可以在上述四层素材池之上
设置“重要作者纵向组”。它不是第五种工作流，也不因作者声望自动取得规则资格；作用是观察同一作者如何
反复提出问题、建构概念、修正理论和处理反例，避免把一篇文章的偶然写法误认成稳定方法。

采用重要作者纵向组时：

1. 仍须逐篇通过语言、地区、文献类型、期刊等级、完整全文及实际方法作业等准入门槛；作者声望不能替代原文核验。
2. 对所有合格文章逐篇制作任务型文章卡，并明确其用途是核心规则、方法补强、历史演变、对抗、边界还是重复例证。
3. 另做作者纵向卡，至少记录：稳定的问题意识、反复使用的概念操作、常见推理链、跨年修正、内部张力、可迁移方法、
   不可迁移的实体结论，以及迁入目标领域时需要增加的保护条件。
4. 将不同重要作者放入交叉对抗，检验其在价值与认知、权力与证明、规范与经验、形式合意与真实能力等方面的差异。
5. “全部用上”是指每篇都有经原文核验的明确训练角色，不等于把每篇结论都写入运行时工作流，也不重复生成同义规则。
6. 新入库文章只有在题录、全文和深度原文读取均就绪后才冻结 key 并计入已完成训练；尚未就绪的列入具名待核批次，
   训练结束前再复查一次，不得依据摘要提前定规则。

### 4.4 数量采用饱和原则

专题工作流的通常规模：

- 试读：12—18 篇，用于定文章卡和标签；
- 可用 v1：30—45 篇高相关素材；
- 较稳定版本：45—60 篇，并覆盖主要反例和方法缺口。

不是每篇都要机械双读。建议：

- 每篇至少完整读取一次；
- 25%—35% 由第二名子代理独立复核；
- 核心分歧、低置信度或新标签必须复核；
- 每批 4—6 篇，连续两批不再产生新规则或实质修订时检查是否达到饱和。

## 5. 子代理训练流水线

### 5.1 冻结素材清单

为每篇记录：

- 题名、作者、来源、年份、原文位置；
- 进入哪一层素材池及理由；
- 是否属于重要作者纵向组、在作者序列中的位置及本篇训练角色；
- 主要方法类型；
- 是否仅作历史、对抗或边界样本；
- 原文是否完整可读、是否已完成可逐页深读。

训练批次开始后不悄悄换文。新增材料进入下一批。

### 5.2 批量精读

每名读取子代理一次处理 4—6 篇，逐篇生成与任务类型对应的文章卡。不得只读摘要、检索片段、引言和结论。

属于重要作者纵向组的文章，在逐篇文章卡之外还要滚动更新作者纵向卡。不得把早期与后期命题压成静态“作者观点”；
应标明哪些方法持续存在，哪些概念、分类、制度方案或适用边界后来发生修正，以及这种变化是否足以修订候选规则。

论文初稿文章卡先记录主路线和辅助模块。教义学路线至少包含：

- 问题如何从规范或实践矛盾中提出；
- 规范来源、位阶、时效与相互关系；
- 竞争观点及作者的反驳顺序；
- 实际使用的解释、概念、类型、要件、法律效果和救济动作；
- 最强反例、边界案件与未处理问题；
- 可迁移方法与不可迁移的实体结论；
- 对应原文页码。

理论—制度建构路线至少包含：

- 所要重构的概念、原则、模式或制度；
- 理论前提及其竞争方案；
- 既有理论或立法为何不足；
- 从基础理论到中层命题、再到制度安排的推理链；
- 机构、权限、程序、措施、效果和救济等制度落点；
- 实施条件、最强反例与不可迁移的实体结论；
- 对应原文页码。

综述文章卡至少包含：

- 综述范围、时间、地域、对象和材料边界；
- 检索或纳入标准；
- 分类轴与分类理由；
- 观点谱系、代表作者、证据类型和真实分歧；
- 共识、争议、演变和研究缺口；
- 从材料总结到作者判断的推理桥梁；
- 可迁移结构、失败风险及原文页码。

### 5.2a 专题初稿的成文技艺卡

既有可靠性卡保留，不从零重做。若可靠性卡没有保存真实标题、篇幅、章节依赖和段落动作，必须重新打开原文逐页读取，
不能凭摘要式旧卡补写。每篇至少有三层：

1. **成文总卡**：路线、文章类型、问题入口、既有精确答案及失败点、中心命题、作者自述贡献与实际成立增量、
   创新类型、理论选择及替代理论、中层命题、评价项、制度动作、标题—摘要—引言—正文—结论兑现、可迁移／不可迁移内容、
   论证缺陷；每项带原文页码并标“作者明示／结构推断／训练综合”。
2. **章节功能图**：真实一级、二级标题、起止页和大致篇幅；逐单元记录局部问题、局部结论、输入、依据、方法、最强竞说、
   输出、前后依赖、印刷结构与推理结构差异，以及删除／调换造成的断裂。
3. **论证动作卡**：每篇选择能覆盖问题转折、研究缺口、中心命题、核心证明、概念／类型、最强反驳、过渡和结尾回收的
   关键段落组；记录主张、材料、推理桥梁、反方、动作顺序、进入／退出、模态强度、限定、转折、引注位置、印刷页、
   最短必要定位及训练者重新表述后的通用动作。

不得复制长段落，也不得把来源句稍作改写后放入运行时材料。所有 schema 字段必须出现；原文确实没有时填 `not_present`，
不得留空、写“略”或用同上代替。

### 5.2b 校准闸门与 schema 完整性

成文技艺训练先用约 8 篇校准集验证 schema。校准完成后必须暂停，交付样例卡、字段完整性、结构原型、OCR／页码问题、
schema 修订建议及旧卡—新卡对照，取得用户确认后才能批量处理其余样本。

每轮至少机器报告：

- 校准集和全部深读集的卡片数；
- 总卡字段应有／实有数；
- 章节功能单元和论证动作卡数量；
- `not_present`、缺字段及原因；
- 独立全文复核数量及占比；
- 原文争议裁决数量。

字段完整只证明记录齐全，不证明判断正确。独立复核和原页裁决仍不可省略。

### 5.3 对抗

对抗子代理不另写一篇总结，只攻击文章卡或候选规则：

- 是否把作者的实体结论误当通用方法；
- 是否把章节顺序误当推理顺序；
- 是否遗漏反方、例外、规范位阶或制度前提；
- 是否把“常见”写成“必要”，把“没检到”写成“学界没有”；
- 是否只因期刊或作者声望而放松检验；
- 是否把少年司法的保护逻辑、刑事责任逻辑或程序保障逻辑中的一方绝对化。

异议必须指向具体字段、命题和原文位置；“感觉不对”不进入裁决。

### 5.4 原文裁决

裁决代理只处理发生争议的字段，重新打开指定原文页，给出：

- 保留；
- 修正；
- 降级为暂定；
- 保留真实争议；
- 删除。

不得以多数票或代理身份决定正确答案。

### 5.5 分别总结规则

不同任务类型及内部路线分别生成规则卡：

```yaml
rule_id:
workflow_type:
scope:
trigger:
required_inputs:
operation:
expected_output:
exceptions:
failure_warning:
supporting_sources:
counterexamples:
status: core | domain_specific | provisional | controversial | rejected
```

跨多篇稳定出现且能承受反例的动作，才进入工作流正文；单篇的漂亮写法只保留为例子。

成文技艺规则还须逐条记录支持论文、反例、作者分布、适用路线、适用题型、不适用边界、作者明示／训练综合性质，
以及最终进入核心工作流、自动附带手册、设计记录或拒绝项。一般规则至少跨 3 篇、2 名作者并承受反例；
单一作者的比喻、句式、固定数字结构、独创标题和个人化文风只能拒绝迁移。结构原型必须由样本归纳，
不得为了符合预设把文章塞进统一章序。

## 6. 从规则生成工作流

每份 PaperPiggy 内置工作流必须保留：

1. 触发条件；
2. 开工前检查；
3. 用户决策点；
4. 完成标准；
5. 最终报告。

正文只保留执行时真正需要的步骤、闸门和失败警告。训练过程、样本统计和长篇方法说明留在设计文档，不塞进运行时工作流。

当成文技艺细则较多时，采用“**核心工作流＋自动附带手册**”：

- 核心工作流保留路由、方案卡、人工闸门、执行顺序、硬失败和完成标准；
- 手册保存有限结构原型、论证动作、篇幅参考、功能性表达、自拟正反例和修改清单；
- 读取主工作流时由产品自动返回磁盘上的用户当前手册；
- 手册不进入顶层工作流列表，不能依赖 Agent 自己想起来再读；
- 用户修改的主工作流和手册均受 normalized＋exact 历史指纹、`.new.md` 旁本和并发创建保护。

从候选规则压缩成运行时正文时，必须另留一份“候选规则 → 运行时条款”映射：逐条记录规则是独立保留、
与哪些规则合并、改成条件模块、只作为争议协议，还是转写为禁止项，并定位到最终模板条款。不得只写
“已压缩进工作流”而让规则去向不可追溯；以后重训先更新映射，再修改运行时模板。

专门版优先于通用版；任务类型优先于主题词。识别不清且会导致选择不同工作流时，只问一个必要问题。

若一个工作流包含多条内部路线，先诊断任务，再向用户提供路线选择卡。每张卡至少包含：

- 路线名称与适配理由；
- 拟定标题；
- 核心研究问题；
- 中心观点；
- 大纲；
- 各部分主要内容；
- 所需规范、理论与事实材料；
- 优势、风险与不适用边界。

明确标出推荐路线，但在用户选择前不进入全文起草。混合题目只确定一条主路线，再叠加必要模块，
不得为“混合型”另造一个常驻版本。

## 7. 验证与迭代

默认使用 3—5 个真实或仿真的未见任务做前向测试：

- 是否正确触发；
- 是否完成目标方法作业；
- 是否忠实使用原文；
- 是否能处理反方和边界案件；
- 是否把专门规则用于合适范围；
- 是否比未使用工作流时减少关键失败。

论文初稿工作流至少测试一个教义学题、一个理论—制度建构题和一个两条路线都可行的混合题，
并检查路线建议和用户选择闸门。综述工作流至少测试一个宽主题、一个窄争点和一个存在实证/规范研究冲突的主题。

完成成文技艺训练的专题初稿不能只测方案卡。应准备约 6 个未见题目，覆盖两条路线、混合题和材料不足／容易夸大创新的压力题：

1. **选路前测试**：明确用户尚未选路，验证会提交两张实质不同的方案卡并停止；
2. **选路后测试**：题面明确“用户已经选择路线并确认提纲”，再合法验证后续正文，不得假装取得用户选择；
3. 两条路线各至少 2 个正文级测试；其余题至少完成引言、核心章节和结论压力测试；
4. 每题同时检查写作设计单、创新诊断、理论操作化、结构原型、章节功能、分节论证契约、来源核验、段落推进、
   首尾兑现、法学表达和原创性；
5. 研究可靠性与写作工艺分别评分，不能相互补分；硬失败仍须完成分项评分以定位根因。

正文级验证必须保存原始输出、来源／页码抽查、两套独立评分、五轮修改记录和失败回源。正文好坏不能只靠字段单测验收。
若使用封存文章作盲测，候选规则和运行时文本先冻结；盲测失败须回到原文卡与候选规则裁决，不能在工作流末尾临时追加题目补丁。
实现通过、迁移安全和产品回归只证明产品可用，不能替代真实题目的正文能力验证。

验证结果按“保留、修改、降级、删除、新增”更新规则。无需匿名比较，也不能用一次漂亮输出代替多任务验证。

## 8. 产品实施提醒

候选工作流经用户确认后，才进入产品实现。实现前重读 `docs/MAINTENANCE.md`，至少同步：

- `src/agent_ws.py` 中一个工作流一个模板；

  首个交付动作、停止闸门和适用边界；不得用同一上下文连续问四题冒充路由验证；
