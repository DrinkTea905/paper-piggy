    📖 新手指引 · 用 Agent 驱动你的专属知识库
    1

    主线 · PaperPiggy + Agent

    顶部「打开专用浏览器」直接打开正常 Chrome 窗口；没有 Chrome 时使用 Edge。已有窗口会直接显示，保留原有标签。新用户首次使用自动建立独立资料，按需登录网站即可；已有旧连接时会先核验沿用，若提示旧浏览器未运行，请先通过原来的方式打开它，再点按钮。按钮本身不会执行投稿、周报或其他任务。

    PaperPiggy 是 Agent 的文献知识引擎。它管理题录、全文、原文位置、检索摘要和综述库；Agent 负责检查知识库、检索文献、精读原文、核验论断、整理成果和持续维护。

    你负责说明研究问题、范围、交付物和证据标准。Agent 负责选择工具、安排步骤，并把可复用成果保存到本机的交付物、综述库和项目记忆中。每次任务开始，PaperPiggy 都会要求 Agent 先完整读取项目记忆（长期偏好，外加工具经验各子域与各研究主题的清单）；任务产生新的长期偏好、决策、进度或关键事实时，也必须在结束前写回这里。

    2

    完成基础建库

    首次向导依次完成：
    · 选择本地检索或 SiliconFlow 云端检索；
    · 连接 Zotero，或选择一个装有 PDF、EPUB、DOCX、Markdown、TXT 的文件夹；
    · 建立题录和语义索引。
    第一版索引可用后即可连接 Agent，全文深索可以按课题分批完成。需要研究现行法时，还可以让 Agent 从官方网页核对完整法规正文，经你确认后写入独立本地法规库；Agent 可同时提交约 150 字检索摘要，经质量检查后随条文一并嵌入。法规会参与统一检索，但不会写入或修改 Zotero。

    3

    连接 Agent

    打开顶部「🤖 Agent」页，选择 Claude Code、Codex 或通用 MCP 客户端，复制应用生成的本机接入命令，在 Agent 会话中运行。接入后先让 Agent 完整读取项目记忆（它会自动只读常读的那部分，各研究主题的详细档案按需再取），再查看知识库状态并搜索一个库内主题。

    4

    布置第一项研究任务

    把四件事说清楚：研究问题、资料范围、交付物、证据标准。Agent 会先按任务类型区分论文初稿与综述，再按领域区分少年司法与其他领域，读取对应工作流。少年司法论文初稿会先读本题的核心文献再谈结构：读的是完整原文（逐页正文与印刷页码），检索片段和摘要都不算读过——骨架是从读到的东西里长出来的，不是从题目里想出来的。骨架搭好后，它会把逐字标题树连同每章准备写什么（回答哪个问题、用什么材料、得出什么判断）先贴给你看一眼；你没有异议它就接着写全文，不会停下来干等。读取主工作流时会自动附带《三大刊结构》——12 篇《中国法学》《法学研究》《中外法学》的逐字标题树与各章实测字数，骨架照真实期刊论文的样子搭。批量精读文献、引证核验和定稿前的独立校核默认派子代理并行做（起草正文各章不派，那是跨章约束）；你说“你自己做”就全程不派，标准一条不减。正文只划禁区、不设配额：破折号、对冲词、“值得注意的是”这类划重点词、“前引／同前注”、正文里出现他人姓名，一概不用。最终论文固定交付可打开并检查过的 DOCX，Markdown 只作中间稿或核验记录。其他领域的论文初稿使用“通用暂用版”，它尚未经过其他部门法训练验证。

    5

    让 Agent 安排深索与检索摘要

    深索把全文拆成可检索片段，并保留页码、章节、标题段落或行号。扫描版 PDF 会在本机完成 OCR。检索摘要帮助系统识别整篇文献的主题，不是原文摘要，也不替代深索。

    让 Agent 围绕当前课题挑选最相关的一批文献，分批完成深索和检索摘要。大型文库可在电脑空闲时逐步扩展。

    6

    让成果进入交付物和综述库

    论文初稿、资料汇编、报告等成品保存在交付物；研究方法、项目记忆与各研究主题的档案、参考格式和定时任务保存在资料库；需要长期复用和更新的结论进入综述库。你核验一页后，Agent 再修改它只会提交待审稿：原核验版继续显示和检索，你可以查看正文、来源与互链的具体差异，再接受并核验、先编辑或放弃。标题、参考来源和版本历史由 PaperPiggy 维护。

    7

    让 Agent 维护知识库

    在 Zotero 加入一批文献后，可以直接说：
    “维护我的 PaperPiggy 知识库。检查新增题录、全文附件、深索、OCR、检索摘要、待更新综述、综述主题归类、孤儿页、断链和过时内容；安全事项直接处理，需要研究判断的事项集中说明。”

    8

    人工控制台、备份与隐私

    · 文献页用于浏览分类、查看处理状态、人工挑选文献和打开原文；“题录查找”输入后会自动显示结果，“全文与相关内容”仍需点击“检索全文”或按 Enter。
    · 综述库用于阅读、核验、查看历史和回滚。
    · 顶栏释放检索内存只清理临时占用；有界面、对话或 Agent 查询时会拒绝，不会中断查询。
    · 应用升级会自动登记兼容的索引契约；只有题录、切块或向量输入规则真正不兼容时才提示相应更新或重建，并显示具体原因。不要因为普通版本升级就主动清空索引。
    · Agent 工作区升级产生的待合并内容与恢复件统一放在 0_Agent资料库 → 升级与备份，不会再散落在技能或说明文件旁边。
    · 设置 → 数据与维护可把综述、Agent 交付物、资料库、分类和人工数据备份为 zip；自动备份在后台执行，页面会显示下次时间和当前进度，正在创建的备份可安全停止。云备份请同步这个静态备份包，不要同步整个数据目录。完整备份会把当前资料、待合并内容和历史备份一起保存。小猪与 Zotero 是两类独立备份任务，可分别选择位置、周期、时刻和保留数量；Zotero 按所选数据目录与全部用户配置的现有内容完整备份，默认保留 2 份。原本缺失的附件只记录状态，不阻止备份；数据库原记录保留，恢复不会补出不存在的文件，也不自动下载或扩大来源。小猪备份可包含已关联专用浏览器的完整资料，排除可再生缓存。首次配置或必要更新后台备份组件需管理员确认，软件运行中也可备份，小猪未打开时仍可按计划执行并在登录后补跑。新版本校验成功后才清理本任务旧版，现有“过时备份”不受影响。备份包不加密，请保护登录资料和密钥。先恢复到新目录验证，原位恢复需你退出相应程序并明确确认；恢复小猪自身还须断开 MCP 并退出小猪，后台完成前不要重开。回退件由你手动清理。Zotero 保持原自动同步设置，异机浏览器可能需重新登录。浏览器热备恢复后，首次打开可能提示“恢复上次会话”，请在专用窗口自行核对并确认，再检查标签和登录状态。
    · 本地检索的待检索文本留在电脑上；SiliconFlow 云端检索和所选 AI 服务会接收完成对应任务所需的文本。API Key 保存在本机设置中。

      它把成果放哪（三个去处，都在本机、人类可读）

      📦 交付物论文 / 资料汇编 / 周报等成品，每主题一个文件夹
      📖 综述库（wiki）可复用的综合页，带页码引用，越用越厚

      前两个可从主页「📦 交付物 / 📚 专属资料库」一键打开查看；记忆是资料库里的 记忆/ 文件夹，按四类分开存放：项目记忆.md（你的偏好、固定规则、已定决策、各主题一行状态）、工具经验/（一个作业子域一份 .md，装跟研究题目无关的作业经验，首行写着「何时该读」）、主题档案/（一个研究主题一份 .md，装该主题的结论与待核项，首行标着「进行中／已完成／已作废」）、变更日志.md（流水账）。每次任务开始，Agent 必须先完整读取 项目记忆.md 加上工具经验与主题档案的清单，未读时 PaperPiggy 会拒绝其他知识库工具；子域与主题的正文默认不读，用得上哪一份才单独取——攒了十几万字的经验也不会每次都灌进 Agent 的上下文。产生新的长期信息时，结束前必须写回对应那一份，写错地方会被拒绝。

      为什么要分开：主题档案的正文默认不进 Agent 的上下文，它要用哪个主题才单独去取。这样你说「这篇推倒重来、以我的新文件为准、旧结论作废」时，旧结论是物理上读不到，而不是靠嘱咐它「别用」——后者不可靠。项目记忆本身也有 3 万字上限，防止它被越写越长、每次开工都拖着一大堆陈年细节。Claude Code、Codex 等仍可保留自己的私有记忆，但私有记忆不能替代这里，写入其中的本项目长期信息也必须同步一份。换任何助手都从这份记忆接着干。

      5

      综述库（wiki）：把问答沉淀成越用越厚的知识

      AI 每答一个问题、读完一篇文献，可把结论写成一页带引用的综述，下次直接命中、不重复劳动。综述页会按来源与现有 AI 主题的重合度自动归类；你也能新建主题、手动固定、搜索和排序。新文献可能推翻旧结论时，Agent 会先标记「过时」并写明理由。AI 新写的页标 🤖 未核验，在检索里会被降权；你核验后，Agent 的后续修改只进入待审稿，原核验版继续显示和检索。打开页面可查看正文差异、来源与互链增删，再选择接受并核验、先编辑待审稿或放弃。每次核验和待审处理都会记入历史。删除自定义主题只会恢复自动归类，不会删除综述。

      6

      深索：让回答回溯到原文位置

      已深索的文献 AI 能读到带原文位置的正文；未深索的只有题录 + 摘要。想某方向问答更扎实，先去「📚 文献」深索它（拆成可检索的小段，可后台慢慢跑，不影响使用）。PDF 没有文字层的页面会自动做本地 OCR；不上传文献、不修改原文件。附件丢失或无法读取会分开提示；文献页筛选器可按正文来源和深索状态查看，每项直接显示当前范围的篇数。

      独立法规库中的原文按条切分，Agent 可直接要求读取“第二十条”，引注也按法规版本和条号生成。法规入库时可一并提交检索摘要；摘要会在预检阶段完成质量检查并绑定确认令牌。未提交时仍照常入库，但会计入“摘要缺失”，Agent 会明确提示调用 submit_agent_summaries 补写。

      应用维护索引时依据的是稳定的产物契约，不是“某个实现文件改过”。兼容升级会自动登记，不要求重新深索；只有切块结构、向量输入配方或检索引擎确实不兼容时才会阻止混用并给出重建原因。Agent 看到普通升级提示时应先读取健康检查详情，不要直接建议清空索引。

      💡 可选增强：检索摘要——深索完，可让 AI 给每篇写一段检索摘要（⚙ 设置 → 建库 → 检索摘要），检索更容易命中这篇；不生成也不影响读取和引用已深索全文。摘要必须通过质量检查才算完成；文献页可筛选“摘要有效 / 异常 / 缺失”。选择“交给 Agent 生成”后，让 Agent 维护知识库时，它会读取正文、修复可处理的缺失/异常摘要并重嵌入；不会改走 PaperPiggy 自动生成摘要的 API。

      🔎 Agent 做发现型检索时会优先铺开不同文献，每篇最多带回 2 段，避免一篇文献挤满结果；选定关键来源后，再做定向深读 / 论断核验，此时可以读取该篇更多证据。内置四条研究工作流和“跨学科发散与补文献”工作流已经按这个顺序执行。

      7

      定时任务：定期帮你盯动态

      让 AI 定期搜集某领域新动态（如每周少年司法周报）。对你的助手说「帮我建一个每周一早上的 XX 周报定时任务」即可：任务定义会写进「资料库 › 定时任务」（换助手也能读、照着重建），成果落「交付物 › 定时任务」，每跑完一次 AI 会依时效内容更新综述库。
      定时触发由你的助手在它自己的日程里执行，PaperPiggy 只登记 / 展示 / 入库；云端检索和 AI 助手是否联网，取决于你的检索引擎与助手配置。

      8

      它会怎么动你的库（权限与安全）

      备份与恢复由你在“设置 → 数据与维护”控制。小猪和 Zotero 分别建立独立恢复点，后台可在软件运行时读取同批卷快照；快照或校验失败会保留已有成功版本，不直接复制活动数据库。小猪备份可包含专用浏览器资料，Zotero 备份包含整个所选 profile 与插件配置，均可能含敏感信息且不加密。Zotero 按所选目录现状备份，原本缺失的附件只记入状态摘要，不阻止成功；保留数据库原记录，恢复不会补出原本不存在的文件。Agent 不得为此补下载或扩大备份来源。恢复先到新目录验证；原位恢复必须由你退出对应程序并确认；恢复小猪自身须先断开 MCP，再退出小猪，完成前不要重开。回退件手动清理。浏览器热备恢复后，首次打开可能提示“恢复上次会话”，由用户在专用窗口自行核对并确认。Agent 不得代为确认，也不得自行关闭程序、覆盖资料、删除历史备份或更改 Zotero 同步设置。

      法规入库有独立双重保护：Agent 必须提交官方 URL、完整正文和版本信息，PaperPiggy 先做结构与哈希预检、保持零写入，向你展示预览；可选检索摘要也在此时完成质量检查并绑定令牌。只有你确认后，原确认令牌才能把同一份内容写进独立法规库，后续不同正文和摘要都不能静默替换，既有摘要也不会被重复入库覆盖。法规快照保存在本机，不会写入或修改 Zotero。

      默认只读检索 + 另存综合，不直接改动你的原始文献或 Zotero；只有你明确要求并通过工具安全闸时，Agent 才能添加来源、建库或深索，从而更新 PaperPiggy 索引。Agent 新写的综述标 🤖 未核验；它更新已核验页时只提交待审稿，不覆盖、不重新索引核验版，只有你接受或编辑保存后才发布为新的核验版。综述页可一键删，是否核验由你决定。原始文献与写回成果保存在本机；云端检索和 AI 助手会接收完成对应任务所需的文本。下面是 AI 必须遵守的写回规约文件（可打开查看它被约束成什么样）：

      设置

      🔎 检索引擎

      检索需要嵌入 + 重排两类专用模型，不是普通聊天 API。云端检索推荐 SiliconFlow，因为它同时提供 PaperPiggy 已适配的两类免费模型；DeepSeek、Kimi 等普通对话 API 不能直接替代检索引擎。⚠️ 建过库后换引擎或模型，旧向量不兼容，应用时会自动重建。

      仅供明确知道服务商同时兼容 /embeddings 和 /rerank 的用户。普通 DeepSeek / Kimi / OpenAI 对话 Key 不能填在这里。

      💬 对话用的 LLM 在「💬 对话」页的「⚙ 模型设置」里设置；填了上面的 SiliconFlow Key 后对话页会自动带出。

      🧠 检索内存

      PaperPiggy 平时只保留轻量的库目录；第一次检索时才加载检索模型和倒排索引。 连续一段时间没有检索后，会自动释放它们，给其他软件腾内存。默认 10 分钟，正在进行的 界面检索、对话检索或 Agent 检索绝不会被中途释放。也可以随时点击顶栏「释放检索内存」； 若仍有查询，PaperPiggy 会说明原因并拒绝释放。

      释放只影响临时内存，不会删除文献、索引或设置；下次检索会自动重新加载。

      怎么选：内存紧张建议 5–10 分钟；经常连续检索建议 30–60 分钟；选“不自动释放”会减少等待， 但本地模型和索引会持续占用更多内存。释放后第一次检索需要重新准备，本地模型通常比云端检索等得更久。
